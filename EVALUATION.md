# Evaluation and interaction contract

No precision, recall, F1, ranking quality, attendance, or user-satisfaction result has been measured. The keyword rules and recommendation weights are provisional.

## Frozen split
`data/split_manifest.json` was reserved before tuning any learned model. It uses union-find to keep identical normalized titles, explicit Localist series URLs, and exact cross-source duplicate keys together. The groups are ordered by their earliest start; 60/20/20 percent of groups are assigned to train/validation/test. The observed record counts are 1,102/206/179. Large recurring groups skew record proportions. Group chronology is approximate, not a strict time cutoff: recurring groups can extend beyond later groups. Audit near-duplicates before training; expand groups and version the manifest if missed relationships are found. Never move examples based on evaluation outcomes. Newly ingested events stay unassigned until an explicit versioned split update.

## Human annotation
Use `python review.py queue` with the server-only service key to export text and hashes without candidate labels. Two reviewers independently label a stratified sample across sources, categories, unknown facts and rare positive tags. Resolve disagreements and save reviewer identity only in the private `tag_reviews` table. Each labels file contains `content_hash` plus the Labels schema fields. `python review.py approve EVENT_ID labels.json --reviewer NAME` rejects stale hashes and unsupported factual quotes. Reviewers may leave ambiguous attributes unknown; do not force binary guesses. Labeling negative examples requires actual human review, not lack of a keyword. Test labels remain locked until final evaluation. Model predictions are never gold labels.

## Trainable baseline
Fit a scikit-learn Pipeline containing TfidfVectorizer(ngram_range=(1,2), min_df=2) and OneVsRestClassifier(LogisticRegression(max_iter=1000, class_weight='balanced')) on HUMAN-REVIEWED TRAIN topics only. Each topic has its own binary classifier. Fit vocabulary, IDF and any feature selection on train only. Choose thresholds on validation only. Report per-tag support, precision, recall and F1 on the reserved test set, plus macro/micro averages. For rare labels lacking positives/negatives in a partition, report insufficient evidence instead of a score. Determine sample-size targets from observed prevalence and confidence intervals rather than an invented universal minimum. Report unknown/excluded labels separately. Factual tags still require quoted evidence and validation even if a classifier predicts them.

## Recommendation evaluation
The current score is 2 per explicit interest match plus Jaccard similarity to saved-event topics. Greedy diversity penalties are 0.4 per repeated organizer and 0.15 per repeated topic. These are provisional choices, not learned or validated results. Candidate generation removes past/cancelled/unknown-status events, applies explicit free-food/free-admission filters, and excludes known restricted events without declared eligibility. Exact cross-source duplicate keys are collapsed; unrecognized duplicates remain a limitation.

Compare against active upcoming events sorted by start time, using identical eligibility and explicit filters. Collect real graded relevance judgments for the same candidate pool and compute nDCG@10, recall@10 and category/organizer coverage. Report uncertainty and sample size; a future time-based evaluation should avoid future interaction leakage. No interaction data exists yet.

## Privacy contract (tracking deliberately disabled)
Preferences and saved IDs are supplied per request; no mandatory accounts or new user table. Existing app localStorage is untouched. The dashboard holds choices only in its session. POST /recommendations does not write preference payloads. If opt-in tracking is later implemented, use a resettable random session identifier, event ID, action in impression/open/save/dismiss, timestamp, and ranking version. Record impressions only after visibility, keep no IP/device fingerprint, do not log preference request bodies, and adopt a short documented retention period (proposed: 30 days) with deletion/export controls. Unseen is not negative, clicking is not attendance, and dismissals are context-specific. Do not enable tracking before implementing consent and deletion. Embeddings/pgvector are deferred until measured value justifies them.
